What is Codeck?

Codeck is a macOS desktop app built with Electron that records meetings — mic-only or system audio + microphone — transcribes speech in real time using Groq Whisper, analyzes the transcript with an AI provider of your choice, and generates a branded PowerPoint deck, all in one flow.

It is built by and for Copods. The AI prompt engine is pre-loaded with Copods company profile data scraped from copods.co — so every proposal deck automatically includes relevant case studies, differentiators, engagement models, and testimonials with no manual input.

Active provider: groq — openai/gpt-oss-120b for analysis, whisper-large-v3-turbo for transcription. Switch any time via AI_PROVIDER in server/.env.
Data lives locally: All meetings, tokens, and generated files are stored in ~/.codeck/. No cloud account required to run the app.

End-to-End Flow

1
Record
User starts mic-only or meeting capture. Web Audio API mixes microphone + system audio into one stream via AudioContext + createMediaStreamDestination().
2
Segment
MediaRecorder restarts every 5 seconds. Each restart writes a fresh WebM container header — making every segment a valid standalone file that Whisper accepts.
3
Transcribe
Each 5-second blob is POSTed to POST /api/transcribe. Text is appended to the running transcript display in real time.
4
Intent + Analyze
User picks a deck type and optional free-text. Transcript + intent sent to POST /api/analyze. The Copods company profile is only injected when the intent signals a proposal or pitch — never for interview, kickoff, or status decks.
5
Generate PPTX
AI JSON passed to POST /api/generate. pptxgenjs builds the deck using ~/.codeck/template.pptx as the brand base.
6
Save & History
File written to ~/.codeck/output/ with a unique base-36 timestamp suffix. Meeting appended to meetings.json for the history view.

Presentation Layer

  • pptxgenjs v3.12 Active
    Generates .pptx programmatically. Uses ~/.codeck/template.pptx as the master for brand colours and fonts. Slide layouts, cover, overview, needs, and closing slides are built via its API.
  • deckType + labels system Active
    AI returns a deckType and a labels object with headings per slide. Builder reads these instead of hardcoded strings — so an interview deck says "Interview Overview" not "Our Understanding".
  • Unique filename per run Active
    Format: YYYY-MM-DD_client-slug_xxxxx.pptx where xxxxx is a 5-char base-36 Date.now() suffix. Prevents overwrites even for the same client on the same day.

Audio Capture

  • Web Audio API Active
    An AudioContext mixes the microphone MediaStream and the system audio stream into one destination node. The mixed output is then passed to MediaRecorder.
  • getDisplayMedia() Active
    Captures system audio: { audio: true, video: false }. On macOS the screen-recording entitlement must be granted in the Info.plist. Used for meeting capture mode only.
  • MediaRecorder API — restart loop Active
    Encodes to WebM/Opus or WebM/PCM (browser-dependent). Restarts every 5 seconds via a Promise-based async loop. Each new recorder instance writes a complete WebM header — required for Whisper to accept the file.
Why restart instead of slicing chunks? WebM is a container format. Only the first ondataavailable chunk contains the header. Slicing raw chunks into separate Blobs produces headerless files that Whisper rejects as invalid media. Restarting the MediaRecorder ensures every 5-second blob is a complete, self-contained file.

Calendar Integration

  • googleapis v173 Active
    Google Calendar API via OAuth 2.0. Scope: calendar.readonly. Tokens persisted in ~/.codeck/google-tokens.json and reused across app restarts.
  • OAuth callback at localhost Active
    Auth flow opens in the system browser. Redirect URI: http://localhost:3001/api/calendar/callback. After code exchange, tokens are saved and the tab can be closed.
  • Event pre-fill Active
    Selecting a calendar event pre-fills both the Meeting Title and Client Name fields. Client name is derived from external attendee email domains, excluding the user's own org domain.

Local Storage

  • ~/.codeck/ Data dir
    All persistent data lives here. Override with DATA_DIR env var. Created on first server start if it doesn't exist.
  • meetings.json History
    Append-only array of every analyzed meeting. Each record stores transcript, AI JSON, deck title, client name, date, and output file path.
  • copods-profile.json AI context
    Scraped copods.co data injected into every proposal prompt: services, case studies, differentiators, engagement models, testimonials, stats, industries, notable clients.
  • template.pptx Brand
    Master theme for all generated decks. Replace this file to instantly apply a new brand — colours, fonts, and layout update across all future generations.

Recording

  • Mic-only mode Active
    Records the user's microphone only. Useful for voice memos or interviews where system audio isn't needed. Requires only microphone permission.
  • Meeting capture mode Active
    Mixes system audio + mic via Web Audio API. Captures both sides of a Google Meet, Zoom, or Teams call with no third-party recording software.
  • Live transcript display Active
    Each 5-second segment is transcribed and appended immediately. Users see the transcript grow in real time — no need to wait for the recording to end.
  • Stop & review flow Active
    Stopping shows the full transcript in the review view. Users can edit the title and client name before generating the deck.
  • Manual transcript paste Active
    The transcript field is editable. Paste any external transcript (Zoom, Otter.ai, Fireflies…) and generate a deck without recording anything.

AI Analysis

  • Intent modal — 6 types Active
    Before generating, a chip-picker asks "What kind of presentation?". Each chip carries an explicit deckType directive injected at the top of the AI system prompt.
  • Free-text intent override Active
    A text field in the intent modal lets users add custom instructions on top of the chip selection — e.g. "Focus on pricing discussion and avoid technical deep-dive".
  • Conditional profile injection Active
    The Copods company profile (services, case studies, differentiators, engagement models, stats) is injected into the AI prompt only when the intent signals a proposal or pitch. Chips that include "Do NOT include" or "do not use the company" as part of their instruction (e.g. Interview Recap) hard-exclude the profile even if the word "Copods" appears elsewhere in the intent text. Default behavior (no chip selected) includes the profile.

PPT Generation

  • 6 deck archetypes Active
    Client Proposal · Pitch Deck · Interview Recap · Project Kickoff · Strategy Deck · Status Update. Each drives a distinct slide structure and tone.
  • Brand template theming Active
    pptxgenjs reads ~/.codeck/template.pptx as master. Replace this one file to instantly update colours, fonts, and background across all future decks.
  • Unique filenames Active
    Every generation writes a new file. Format: 2025-06-28_client-name_a3b7f.pptx. Never overwrites a previous version.
  • Org branding via env Active
    ORG_NAME and ORG_TAGLINE appear on cover and closing slides. Change these to white-label the app for a different org without touching code.
  • Open in Finder Active
    After generation, a button reveals the .pptx in the Finder output folder via Electron's IPC showInFolder bridge.

Calendar

  • Google Calendar OAuth Active
    One-time browser auth. Tokens stored in ~/.codeck/google-tokens.json. Read-only scope — app never modifies calendar data.
  • Upcoming events list Active
    Shows next 10 events. Selecting one pre-fills both Meeting Title and Client Name before recording begins.
  • Client name derivation Active
    Server inspects attendee emails, picks the first external domain (not the user's org). Falls back to the event summary as the title.

Meeting History

  • Persistent log Active
    Every analyzed meeting appended to ~/.codeck/meetings.json. History view shows all past sessions sorted by date.
  • Detail view Active
    Click any history card to see the full transcript, AI summary, client details, and a Regenerate button for a new deck from the same transcript.
  • Re-generate from history Active
    Both the detail view and the history card have a Generate PPT button. Both open the intent modal — user picks a deck type and the saved transcript is re-analyzed.
  • Inline title rename Active
    A pencil icon next to the meeting title in the detail view opens an inline input. Saving sends a PATCH /api/meetings/:id to update meetings.json and updates the in-memory list — no re-fetch needed. Title persists across navigation via meetingsDirty flag: history only re-fetches when a new meeting is actually saved.

Transcription Options

  • Groq Whisper Default
    whisper-large-v3-turbo via Groq REST. Fastest option — sub-second latency on Groq's LPU for a 5-second segment. Language: English.
  • Gemini inline audio When gemini
    Gemini 2.0 Flash accepts base64 audio as inline data. Same API key covers both transcription and analysis — no separate transcription account needed.
  • OpenAI Whisper-1 When openai
    OpenAI's original Whisper model via the audio.transcriptions endpoint. Accepts WebM directly.
  • Claude — Groq fallback When claude
    Claude does not support audio input. When AI_PROVIDER=claude, transcription still uses Groq Whisper — both keys must be set.

AI Provider Comparison

Groq — Default

  • LLM model Active
    openai/gpt-oss-120b. JSON mode enforced via response_format: { type: 'json_object' }. Temperature 0.4 for consistent structured output.
  • Transcription model Active
    whisper-large-v3-turbo. Fastest Whisper variant — optimised for Groq's LPU. Sub-second latency per 5-second segment. Language: English.
  • Web search None
    LLaMA on Groq has no grounding tools. Content comes entirely from the transcript and Copods profile.
  • Cost Free tier
    Generous free tier with rate limits. Sufficient for regular internal Copods use with no billing required.

Google Gemini

  • LLM model gemini-2.0-flash
    JSON mode via responseMimeType: 'application/json'. Faster and cheaper than Pro — sufficient for structured deck generation.
  • Transcription Inline audio
    Audio sent as base64 inline data — no separate transcription step. Same model and same API key cover both.
  • Web search Built-in
    Google Search grounding via tools: [{ googleSearch: {} }]. Up to 3 topics searched per meeting. Source URLs captured from grounding metadata and stored in webFindings.

OpenAI GPT-4o

  • LLM model gpt-4o
    Responses API with web_search_preview tool. JSON extracted from message content block — Markdown fences stripped before parsing.
  • Transcription whisper-1
    OpenAI's original Whisper via audio.transcriptions.create(). Accepts WebM audio natively. Slower than Groq Whisper.
  • Web search Built-in
    Real-time web results via web_search_preview tool — baked into the single analysis pass.
  • Cost Paid only
    No free tier for GPT-4o via API. Billing must be enabled on platform.openai.com.

Anthropic Claude

  • LLM model claude-sonnet-4-6
    Messages API with web_search_20250305 tool. JSON in text content blocks — Markdown fences stripped before parsing. Max tokens: 4096.
  • Transcription Groq fallback
    Claude does not accept audio input. When AI_PROVIDER=claude, the transcription route still calls Groq Whisper — both GROQ_API_KEY and ANTHROPIC_API_KEY must be set.
  • Web search Built-in
    Native web_search tool populates webFindings in the JSON output automatically.
Near-Term Improvements

Short Horizon

  • Editable transcript before analysis Planned
    Allow users to edit the auto-transcript in the review view to fix Whisper errors, remove filler words, or correct misattributed speech before hitting Generate.
  • Transcription progress indicator Planned
    Show a running word count or waveform animation during recording so users know each 5-second segment is being processed and not silently dropped.
  • Whisper hallucination filter Planned
    Post-process transcription output to strip common Whisper hallucinations — "Thank you for watching", "Subscribe", silence-padding phrases. Configurable word blocklist in .env.
  • Provider fallback chain Planned
    If the primary provider returns a rate-limit or server error, automatically retry with a configured secondary. E.g. Groq → Gemini → OpenAI. Chain order set in .env.
  • Recording pause / resume Planned
    A pause button that halts the 5-second loop without ending the session. Resume from where it left off — useful for bio breaks or off-record conversations mid-meeting.
  • Meeting search & filter in history Planned
    Full-text search across saved transcripts and client names. Filter by deck type or date range. Currently the history list has no filtering at all.
Bigger Features

Future Capabilities

  • Speaker diarization Future
    Identify who said what. Groq Whisper v3 supports word-level timestamps — could combine with speaker labels to produce "Client: …" vs "Copods: …" attribution in the deck.

    Open a WebSocket between renderer and server to stream partial results as each segment completes, rather than appending full-segment text in one shot.
  • PDF export Future
    Generate a PDF alongside the PPTX via pptxgenjs export or LibreOffice headless. Useful for sharing with clients who don't have PowerPoint.
  • Action item tracker Future
    Surface the nextSteps array from AI JSON as a persistent checklist. Track status across sessions. Optional email digest of open items.
  • Multi-language transcription Future
    Whisper supports 99 languages. Add a language selector to the recording UI and pass the language param to the transcription API call.
  • Auto deck-type detection Future
    Before showing the intent modal, run a lightweight classification on the first N words of the transcript to suggest the most likely deck type as the default chip selection.
  • Cloud sync for history Future
    Optionally sync meetings.json to Supabase or Firebase so history is shared across devices or team members. Requires an auth layer.
  • Org profile auto-refresh CLI Future
    A CLI command to re-scrape copods.co and refresh ~/.codeck/copods-profile.json so the AI prompt always uses up-to-date case studies and client lists.

API Routes

MethodRouteDescription
POST /api/analyze Transcript + deckIntent + meetingTitle → active AI provider → structured JSON for PPT.
POST /api/transcribe Multipart audio blob → Groq Whisper / Gemini / OpenAI Whisper-1 → plain text. Temp file deleted after call.
POST /api/generate AI JSON (meetingData) → pptxgenjs → writes .pptx to output dir → returns filename + path.
GET /api/files Lists all .pptx files in the output directory. Used by the history view.
GET /api/calendar/events Returns next 10 Google Calendar events. Requires valid tokens in google-tokens.json.
GET /api/calendar/auth Initiates Google OAuth — redirects to Google's consent screen in the system browser.
GET /api/calendar/callback OAuth redirect target. Exchanges auth code for tokens, saves to disk.
GET /api/provider Returns active provider name, LLM model, and transcription model. Used for status display.
GET /api/config Returns { provider: 'groq' }. Lightweight config fetch on renderer startup.
GET /api/health Returns { status: 'ok' }. Electron main process polls this before showing the window.
GET /api/meetings Returns full meetings.json array sorted by date descending. History view source.
POST /api/meetings Appends a new meeting record to meetings.json after recording + analysis. Sets meetingsDirty=true in the renderer to trigger a re-fetch on next history view.
PATCH /api/meetings/:id Updates meetingTitle or clientName for a single meeting in-place. Used by the inline title rename in the detail view — no full re-fetch required.

AI JSON Schema

Every provider returns this same structure. The builder reads all fields. Non-proposal decks must have whyCopods and engagementModel set to null.

{
  "deckType":         // proposal | interview | kickoff | strategy | status | other
  "labels": {
    "cover":         // ALL-CAPS label on cover — e.g. CLIENT PROPOSAL, INTERVIEW RECAP
    "overview":      // Slide 2 heading
    "needs":         // Slide 3 heading
    "closing":       // Closing slide — use \n for line break
  },
  "orgName":          // Always "Copods" (or ORG_NAME env value)
  "clientName":       // Person / company the meeting is ABOUT — never the platform
  "clientIndustry":   // Their domain / sector
  "meetingDate":      // ISO 8601
  "deckTitle":        // Title on the cover slide — must match meetingTitle if provided
  "executiveSummary": // 2-3 sentences matching the deckType purpose
  "clientNeeds":      // [{ title, description }]
  "proposedSolutions":// [{ title, subtitle, keyPoints[], stat }]
  "whyCopods":        // null for non-proposal — or { keyPoints[], relevantCaseStudy }
  "engagementModel":  // null for non-proposal — or { name, description, phases[] }
  "nextSteps":        // [{ item, owner, dueDate }]
  "webFindings":      // [{ topic, query, summary, sources[] }] — from web search providers
}
